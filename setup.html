Si empiezas de cero, léela primero. Si ya estás en una máquina, úsala como referencia.

Qué NO es esto: no es un cheatsheet de comandos para copiar. Para eso está la sección CHEATSHEET del knowledge base. Aquí lo que importa es el porqué y el cuándo: el criterio que hace que un comando sirva. Los writeups traen los comandos en contexto; esta guía trae el andamiaje que los une.

01 · ENTORNO & CONEXIÓN

El primer muro real de todo principiante: llegar a la máquina.

Qué necesitas

Cuenta en Hack The Box (VIP para máquinas retiradas), Kali Linux funcionando (aquí, sobre VirtualBox), y paciencia para atascarte. Atascarse es el proceso, no un fallo del proceso.

Conectarse a la VPN

Descarga tu .ovpn del panel de la máquina en HTB y conéctate. La terminal se queda colgada mostrando logs: eso es correcto, no la cierres. Trabaja en una terminal nueva.

sudo pkill openvpn                        # mata cualquier VPN previa (una a la vez)
sudo openvpn ~/htb/tu_archivo.ovpn         # espera "Initialization Sequence Completed"
ip a show tun0                            # debe existir con IP 10.10.x.x
ping -c 3 <IP_OBJETIVO>                   # confirma línea con la máquina
UNA VPN A LA VEZSi levantas una segunda VPN sin cerrar la anterior, Linux crea tun1 (porque tun0 sigue ocupada) y aparecen errores route ... File exists. Siempre sudo pkill openvpn antes de reconectar.

Problemas típicos de VPN

Cada error dice una cosa distinta. Aprender a leerlos es media batalla:

Lo que vesQué significaQué hacer
TLS handshake / key negotiation timed outTus paquetes salen, nadie responde. Típico de UDP tras una VM/red restrictiva.Protocolo TCP 443, baja un .ovpn nuevo.
Connection refused (TCP)Tu paquete llegó y el destino dijo "no". Ese servidor no acepta ahora.Cambia de servidor VPN.
Destination Host UnreachableEl gateway de HTB no encuentra el host.La IP de la máquina cambió: verifícala en la web.

Diagnóstico de abajo hacia arriba: antes de culpar a la VPN, confirma que Kali tiene internet (ping 8.8.8.8) y DNS (ping google.com). Si ambos van, el problema es de la VPN; si ninguno va, es la red de la VM.

LA IP NO ES ETERNALa IP de una máquina de HTB cambia si la reinicias, si cambias de servidor VPN, o entre sesiones. Antes de atacar, confirma siempre la IP actual en la web. Nunca la asumas de memoria.

02 · METODOLOGÍA

Los hábitos que separan a quien entiende de quien copia comandos.

Una carpeta por máquina

Desde el día uno: cada máquina, su carpeta; todo guardado, nada suelto. Y en nmap, guardar siempre con -oA, nunca escanees sin dejar registro.

mkdir -p ~/htb/<maquina>/nmap && cd ~/htb/<maquina>

Mide antes de tocar

Cuando algo falle, no cambies cinco cosas a la vez esperando que una funcione. Haz una prueba, lee el resultado, y deja que el resultado te diga qué cambiar. Un error que cambia cuando tocas algo es buena señal: significa que tu cambio tuvo efecto y estás cercando el problema.

Anota las tasks a medida

Si resuelves en Guided Mode, copia cada respuesta apenas la marcas, no al final. Muchas tasks se resuelven tempranísimo (los puertos con el primer nmap) y se olvidan al llegar al cierre. Anotar sobre la marcha hace que tu writeup salga completo solo.

Higiene de herramientas

Un dominio por análisis en BloodHound (limpia la base antes de cargar otro lab, o los grafos se contaminan). Limpia entradas viejas de /etc/hosts entre labs. Ordena para no confundirte a ti mismo.

03 · RECONOCIMIENTO

El primer movimiento de todo pentest: qué puertas hay abiertas.

El TTL delata el sistema operativo

Antes de escanear, el ping ya te dice ante qué estás. El TTL parte en un valor por SO y baja 1 por salto de red:

TTL que vesSistema operativo probable
~63 (parte en 64)Linux / Unix
~127 (parte en 128)Windows

El flujo de nmap

Dos pasos: primero un barrido de todos los puertos, luego un escaneo detallado solo de los que salieron abiertos.

nmap -p- --min-rate 1000 -oA nmap/allports <IP>        # los 65535 puertos, rápido, guardado
nmap -sCV -p <PUERTOS_ABIERTOS> -oA nmap/detail <IP>  # versión (-sV) + scripts (-sC)

-p- no se salta puertos raros; --min-rate 1000 acelera; -oA guarda en tres formatos; -sCV es tu radar: qué servicio y versión corre cada puerto.

Elegir por dónde entrar

Piensa en cada puerto como una puerta y pregúntate cuánta superficie ofrece. Regla que se repite en toda la serie: atacas por donde puedes hacer algo, no por donde estás bloqueado. SSH/WinRM sin credenciales están cerrados con llave (los guardas para después); la web (HTTP) suele ser la superficie más rica para empezar.

MUCHOS PUERTOS = DOMAIN CONTROLLER2-3 puertos es una Linux típica. 20+ puertos con Kerberos (88) + LDAP (389/636) + SMB (445) + DNS (53) juntos = un Domain Controller de Active Directory. La explosión de puertos es, en sí misma, una pista.

04 · REFLEJOS DEL OFICIO

Patrones que se aplican una y otra vez, máquina tras máquina.
SituaciónReflejo
Encuentro una versión de software específica y rara (-dev, beta, RC)Buscar de inmediato si tiene vulnerabilidad/CVE pública conocida. Una versión de desarrollo en producción es bandera roja.
La web no muestra nada obvio al navegarlaMirar lo que hay por debajo: cabeceras HTTP con curl -I revelan servidor, SO y versiones.
Consigo unas credenciales en un servicioProbarlas en todos los demás servicios (password reuse). La gente reutiliza contraseñas; casi siempre pagan.
Voy a ejecutar un exploit descargadoLeerlo antes (cat). Entender qué hace = separar entender de copiar. Nunca a ciegas.
Tengo un binario poco común con permisos (SUID/sudo/capabilities)Buscarlo en GTFOBins, usando la sección del permiso que TENGO (Sudo ≠ Capabilities ≠ SUID).
Consigo un hash de contraseñaCrackearlo offline (silencioso, ilimitado). john si no hay GPU; hashcat con GPU. rockyou como diccionario.
Estoy en una máquina de Active DirectoryMapear el dominio en /etc/hosts (obligatorio: muchas herramientas Kerberos fallan por IP). Enumerar anónimo antes que nada.
Consigo credenciales nuevas en ADValidarlas (netexec), ver dónde entran (SMB/WinRM), y mapear el dominio con BloodHound para el camino a Domain Admin.

06 · CONCEPTOS BASE

El vocabulario mínimo que verás en cada writeup.
Shell
Acceso a la línea de comandos de la máquina objetivo. Pasar de "mirar desde afuera" a "estar adentro".
Reverse shell
Conseguir una shell sin credenciales haciendo que la víctima te llame de vuelta a tu IP+puerto (no al revés).
Foothold
El primer acceso conseguido en una máquina, normalmente como un usuario de pocos privilegios.
Privesc
Escalada de privilegios: pasar de usuario común a administrador total (root en Linux, Administrator/Domain Admin en Windows).
Hash
Representación cifrada de una contraseña. No es la contraseña, pero se puede crackear offline o, en Windows, usar directo (Pass-the-Hash).
User / Root flag
Los dos "trofeos" de una máquina HTB: user.txt (usuario normal) y root.txt (administrador). Prueban el compromiso.
$ vs #
El prompt te dice quién eres en Linux: $ = usuario normal; # = root (superusuario).
RCE
Remote Code Execution: ejecutar tus comandos en un servidor remoto explotando una vulnerabilidad.
IDOR
Acceder a objetos ajenos cambiando un ID predecible en una URL, porque la app no verifica permisos.
Password reuse
Reutilización de la misma contraseña en varios servicios. Un par de credenciales puede abrir varias puertas.
Pass-the-Hash
Autenticarse en Windows con el hash NTLM de una cuenta, sin conocer la contraseña en texto.
DCSync
Abusar de la replicación entre Domain Controllers para pedirle al DC todos los hashes del dominio.

¿Quieres más profundidad por técnica? El GLOSARIO y el knowledge base cubren cada área con prerequisitos, detección y mitigación.

CHECKLIST DE ARRANQUE

Antes de cada máquina, recorre esto.
  • VPN: mata las previas (sudo pkill openvpn), conecta, espera Initialization Sequence Completed.
  • tun0: verifica que existe con IP 10.10.x.x (ip a show tun0).
  • IP objetivo: confírmala en la web (cambia entre sesiones) y comprueba línea con ping.
  • Carpeta: crea ~/htb/<maquina>/nmap y trabaja ahí.
  • TTL: mira el ping: ¿63 (Linux) o 127 (Windows)?
  • Recon: nmap -p- y luego -sCV, guardando con -oA.
  • Decisión: elige la puerta con más superficie, no la que esté cerrada con llave.
  • Si es AD: mapea el dominio en /etc/hosts antes de usar herramientas Kerberos.
  • Tasks: anota cada respuesta apenas la resuelvas, no al final.
