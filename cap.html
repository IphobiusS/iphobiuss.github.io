HTB LINUX EASY IDOR CAPABILITIES

Guía para principiantes de la máquina Cap de Hack The Box. No es una lista de comandos para copiar y pegar: explica qué hacer, por qué hacerlo y cómo se decide cada paso. Si es tu primera máquina, léela de arriba a abajo. El objetivo es que al terminar no sepas "cómo se resuelve Cap", sino cómo se piensa frente a un objetivo. Antes de empezar necesitas: una cuenta en Hack The Box (Cap es retirada, requiere VIP salvo cuando es la máquina activa), Kali Linux funcionando (aquí, sobre VirtualBox), y ganas de atascarte. Atascarse es el proceso, no un fallo del proceso.

El método que recorre toda la guía: mide antes de tocar. Cuando algo falle, no cambies cinco cosas a la vez esperando que una funcione. Haz una prueba, lee el resultado, y deja que el resultado te diga qué cambiar.

00 · CONECTARSE AL LAB (VPN)

El primer muro real. Casi ningún writeup lo explica.

Ordena tu espacio de trabajo

Regla de oro desde el día uno: cada máquina, su carpeta. Todo guardado, nada suelto.

mkdir -p ~/htb/cap/nmap
cd ~/htb/cap

Descarga tu .ovpn y conéctate

En el panel de la máquina en HTB hay un botón Connect to ... with OpenVPN. Ahí eliges servidor y protocolo y descargas tu archivo .ovpn, tu llave para entrar a la red del laboratorio.

sudo openvpn ~/htb/cap/tu_archivo.ovpn

Esta terminal se queda colgada mostrando logs. Es correcto: mientras esté abierta, tu VPN está activa. No la cierres. Abre una terminal nueva para trabajar.

Busca la bandera verde

En los logs, la línea que confirma que estás dentro:

Initialization Sequence Completed

Los avisos WARNING y DEPRECATED OPTION no son errores: son de una config algo antigua de HTB y no te afectan. Distinguir un aviso de un error real es media batalla del troubleshooting.

Verifica la interfaz tun0

ip a show tun0

Busca una interfaz tun0 con IP tipo 10.10.x.x. Si aparece, tienes identidad dentro del lab.

Problemas típicos de VPN (y cómo se leen)

Estos tres errores frenan a casi todo principiante. La clave: cada uno dice una cosa distinta.

Lo que vesQué significa realmenteQué hacer
TLS handshake / key negotiation timed outTus paquetes salen pero nadie responde. Típico de UDP tras una VM/red restrictiva.Cambia el protocolo a TCP 443 y baja un .ovpn nuevo.
Connection refused (TCP)Tu paquete sí llegó y el destino dijo "no". Ese servidor no acepta conexiones ahora.Cambia de servidor VPN.
Destination Host UnreachableEl gateway de HTB no encuentra el host. Casi siempre: la IP de la máquina cambió.Verifica la IP actual en la web.

Diagnóstico de abajo hacia arriba. Antes de culpar a la VPN, confirma que tu Kali tiene internet:

ping -c 3 8.8.8.8      # ¿hay salida a internet?
ping -c 3 google.com   # ¿funciona el DNS?

Si ambas responden → tu internet está sano y el problema es de la VPN (servidor/protocolo). Si ninguna responde → es la red de tu VM (revisa el adaptador en VirtualBox). Para probar si un puerto del servidor VPN es alcanzable sin la VPN:

nc -zv <IP_DEL_SERVIDOR_VPN> 443
NOTA DE ORO · TROUBLESHOOTINGUn error que cambia cuando tocas algo es buena señal: significa que tu cambio tuvo efecto y estás cercando el problema. En Cap, el arreglo final fue cambiar de servidor VPN, porque el original rechazaba la conexión.
LA IP NO ES ETERNALa IP de una máquina de HTB no es fija: cambia si la reinicias, si cambias de servidor VPN, o entre sesiones. Antes de atacar, confirma siempre la IP actual en la web. En esta guía es 10.129.103.82; la tuya será distinta, reemplázala en todos los comandos.

01 · RECONOCIMIENTO

El primer movimiento de todo pentest: qué puertas tiene abiertas el objetivo.

Barrido de todos los puertos

cd ~/htb/cap
nmap -p- --min-rate 1000 -oA nmap/allports 10.129.103.82

-p- escanea los 65535 puertos, no solo los comunes. --min-rate 1000 acelera. -oA guarda el resultado en tres formatos: guardar siempre, nunca escanees sin dejar registro.

PORT   STATE SERVICE
21/tcp open  ftp
22/tcp open  ssh
80/tcp open  http

Escaneo detallado de los abiertos

nmap -sCV -p 21,22,80 -oA nmap/detail 10.129.103.82

-sCV = -sV (versión de cada servicio) + -sC (scripts básicos de reconocimiento). Tu radar inicial.

Interpretar: elegir por dónde entrar

Piensa en cada puerto como una puerta y pregúntate cuánta superficie ofrece:

PuertoServicioLectura del pentester
22SSHControl remoto por terminal cifrada, pero pide credenciales que aún no tienes. Puerta cerrada con llave. Más "salida" que "entrada": el sitio a donde llegas después.
21FTPTransferencia de archivos. A veces permite anonymous sin credenciales. Buen segundo lugar.
80HTTPLa superficie más grande y rica: páginas, formularios, funciones, código, rutas, parámetros. Cada una es una posible vía.

Decisión: empezamos por HTTP. No por corazonada, sino por criterio: la web casi siempre ofrece más por dónde tirar.

02 · EXPLORAR LA WEB · IDOR

Antes de cualquier herramienta sofisticada, se mira con los ojos.

Reconocimiento web tranquilo

Abre Firefox en Kali y navega a http://10.129.103.82. Explora como un usuario curioso, sin buscar todavía "la vulnerabilidad". Primero entiende qué es la aplicación:

→ Es un "Security Dashboard".
→ Ya estás logueado como un usuario llamado Nathan (arriba a la derecha), sin haber puesto contraseña. Eso significa algo: hay usuarios, y la app te trata como uno.
→ En el menú hay una función que llama la atención: "Security Snapshot (5 Second PCAP + Analysis)".

REGLALa fase de reconocimiento tranquilo es el 80% del trabajo. Casi nadie la explica. No busques la vulnerabilidad: entiende primero qué hace la aplicación.

Vigila la URL

Haz click en Security Snapshot. La página trabaja y te redirige. Mira la barra de direcciones:

http://10.129.103.82/data/1

Esa forma, una ruta que termina en /algo/<número>, es una de las cosas más jugosas que un pentester puede encontrar en una web. El data es la sección; el 1 es el ID de tu scan.

La hipótesis y la prueba

La app te asignó a ti el ID 1. Pregunta del pentester: ese 1 es mío. ¿Y si lo cambio por otro número? Nada te impide editarlo a mano en la barra de direcciones.

URLResultadoInterpretación
/data/10 paquetesTu scan. Vacío porque en tus 5 s no hubo tráfico.
/data/2"No existe"Nadie generó ese scan todavía.
/data/072 paquetes, 69 TCPUn scan que NO generaste tú. Datos de otra persona.

▚ IDOR: Insecure Direct Object Reference

Accediste a datos que no son tuyos, simplemente pidiéndolos por su ID. La aplicación no verificó si ese scan te pertenecía.

Ocurre cuando una app usa un identificador predecible (un número secuencial: 0, 1, 2…) para referirse a objetos y no comprueba si el usuario tiene permiso para acceder a ese objeto concreto. Cambias el número y ves cosas ajenas. Está en el OWASP Top 10 bajo Broken Access Control, y es de las vulnerabilidades más comunes en aplicaciones reales.

MATIZ: ACCESO ≠ SUPLANTACIÓNAl ver /data/0 sigues siendo Nathan (tu sesión no cambia). Eso no contradice la vulnerabilidad: es la vulnerabilidad. No necesitas convertirte en otro usuario para robar su información: basta con pedir su objeto por el ID. Confundir "ver lo de otro" con "ser otro" es un error clásico de principiante.

03 · ANÁLISIS DEL PCAP

Wireshark asusta la primera vez, pero es más simple de lo que parece.

▚ ¿Qué es un PCAP?

PCAP = Packet Capture (captura de paquetes). Es una grabación de todo el tráfico de red que pasó por una máquina durante un período: quién habló con quién, por qué puerto y, lo crucial, el contenido de esas comunicaciones.

¿Por qué es oro para un pentester? Porque muchos protocolos viejos envían la información sin cifrar, en texto plano. Si un usuario se autenticó con uno de ellos mientras la captura corría, su usuario y contraseña quedaron grabados dentro del PCAP, legibles.

Cuál PCAP importa

Solo un PCAP con tráfico real puede esconder credenciales. /data/1 tenía 0 paquetes → nada dentro. /data/0 tiene 72 paquetes → el único con comunicaciones reales. El PCAP con datos sensibles es el 0.

Descargar y filtrar

En la página de /data/0, busca el botón de descarga del archivo de captura (el .pcap crudo, no el resumen de números). En Kali suele abrirse directo en Wireshark, que muestra una fila por paquete.

No leas las 72 filas una por una. Piensa qué protocolo, de los abiertos, envía credenciales en texto plano. SSH va cifrado (ahí no lees nada), pero FTP no cifra nada. En la barra de filtros de Wireshark, escribe:

ftp

y Enter. La lista se reduce solo al tráfico FTP.

Leer las credenciales

Mira la columna Info. En FTP cada acción aparece casi como lenguaje humano. Busca Request: USER (el nombre de usuario) y Request: PASS (la contraseña):

Request: USER nathan
Request: PASS Buck3tH4TF0RM3!
TRUCO DE WIRESHARKClick derecho en cualquier paquete FTP → Follow → TCP Stream. Wireshark arma toda la conversación FTP completa en una ventana, ordenada y legible de corrido. Una de las funciones más útiles del programa; anótala.

Credenciales obtenidas: nathan / Buck3tH4TF0RM3!

04 · ACCESO INICIAL

Password reuse: el eslabón que convierte una fuga en un shell.

La pregunta clave

Tienes credenciales de FTP. La pregunta del pentester: cuando encuentro un usuario/contraseña en un servicio, ¿los pruebo en los OTROS servicios de la misma máquina? Muchísima gente reutiliza la misma contraseña en todos lados. SSH estaba abierto (puerto 22) y solo necesitaba credenciales. Ahora las tenemos.

Conectarse por SSH

ssh nathan@10.129.103.82

La primera vez pregunta por la autenticidad del host → escribe yes. Luego pide la contraseña: Buck3tH4TF0RM3!. No verás nada al escribir (ni asteriscos ni puntos): es normal en Linux. Escríbela completa y Enter a ciegas.

Si funciona, el prompt cambia de iphobiuss@kali a nathan@cap:~$. Eso significa que estás dentro de la máquina víctima. A eso se le llama conseguir un shell.

La user flag

ls
cat user.txt   # -> 64c77ba6f9da29d6e022e470a40f2a67

Esa es la user flag. Pero nathan es un usuario normal, sin privilegios de administrador. El objetivo final es llegar a root.

05 · ESCALADA DE PRIVILEGIOS

De usuario común a root: capabilities + GTFOBins.

▚ ¿Qué son las capabilities?

En Linux, en vez de ejecutar un programa con todo el poder de root (peligroso), se le puede dar un permiso especial y acotado: una capability. El problema es que algunas, en el binario equivocado, se pueden abusar para escalar a root. La más peligrosa es cap_setuid, que permite a un programa cambiar su identidad de usuario, incluso a root.

Buscar binarios con capabilities

getcap -r / 2>/dev/null

getcap lista capabilities; -r / busca recursivo desde la raíz (toda la máquina); 2>/dev/null manda a la basura los miles de errores "Permission denied" para que solo veas lo útil. Lo vas a usar muchísimo.

/usr/bin/python3.8 = cap_setuid,cap_net_bind_service+eip
/usr/bin/ping = cap_net_raw+ep
/usr/bin/traceroute6.iputils = cap_net_raw+ep
/usr/bin/mtr-packet = cap_net_raw+ep
/usr/lib/.../gst-ptp-helper = cap_net_bind_service,cap_net_admin+ep

Las de cap_net_raw / cap_net_bind_service son de red, no sirven para root. La única con cap_setuid es Python: /usr/bin/python3.8. Un binario que puede convertirse en root y que además ejecuta cualquier código que le escribas: una llave maestra que te deja escribir tus propias órdenes.

GTFOBins: la referencia obligatoria

No hace falta memorizar la sintaxis. GTFOBins cataloga binarios de Linux y exactamente cómo abusar de cada uno según el permiso que tenga (SUID, Sudo, Capabilities…).

ERROR DE NOVATO MÁS COMÚNGTFOBins tiene varias secciones por binario, una por tipo de permiso. Usa la que corresponde a TU permiso. Tú tienes una capability → usa la sección Capabilities, no la primera que veas.

La sección Capabilities de python muestra:

python -c 'import os; os.setuid(0); os.execl("/bin/sh", "sh")'

Léelo: hace justo las dos cosas que predijimos. os.setuid(0) → "conviértete en el usuario 0" (el UID 0 es root; solo funciona porque Python tiene cap_setuid). os.execl("/bin/sh","sh") → "ábreme una shell".

Ejecutar (con la ruta real)

El binario con la capability es python3.8, así que usa la ruta exacta. En la terminal de nathan:

/usr/bin/python3.8 -c 'import os; os.setuid(0); os.execl("/bin/sh", "sh")'

El prompt cambia de $ (usuario normal) a # (superusuario). El # es, en el mundo Linux, el símbolo de root. Confírmalo:

whoami   # -> root
id       # -> uid=0(root) ...

La root flag

cat /root/root.txt   # -> 268ae2e96af7256c928d718f8717f1b9

Máquina comprometida por completo. User flag + root flag.

CONCEPTOS TRANSFERIBLES

Cap es solo el vehículo. Esto sirve para cualquier máquina.
  • Método: mide, lee el resultado, cambia una sola cosa. Un error que cambia es progreso. Diagnostica de abajo hacia arriba (¿internet? → ¿DNS? → ¿VPN?).
  • La IP objetivo no es fija. Confírmala en la web antes de cada sesión.
  • Recon primero, siempre. nmap -p- para no perder puertos; -sCV para versiones; guarda con -oA.
  • Elegir por dónde entrar es criterio, no azar. La web suele ofrecer más superficie.
  • IDOR: ID secuencial en la URL + sin control de acceso = enumerar objetos ajenos. Acceso ≠ suplantación.
  • Protocolos sin cifrar (FTP, HTTP, Telnet) filtran credenciales en un PCAP. Fíltralos en Wireshark; usa Follow TCP Stream.
  • Password reuse: unas credenciales de un servicio se prueban en todos los demás. Casi siempre pagan.
  • Escalada por capabilities: getcap -r / 2>/dev/null para encontrarlas; cap_setuid es la joya; GTFOBins para la técnica, usando la sección del permiso correcto.
  • $ vs #: el prompt te dice quién eres. # = root.
